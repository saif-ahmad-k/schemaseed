Mock data from a CREATE TABLE statement

A schema already describes the rows you need. A column named email should be an email. created_at TIMESTAMP should be a timestamp. A CHECK list such as status IN ('draft', 'active') should only use those words.

SchemaSeed reads that statement in the browser. Nothing is uploaded. You can export the rows as JSON, CSV, or SQL INSERT statements.

What the parser uses

  • The table name and each column name.
  • The SQL type, including wrappers such as Nullable and LowCardinality.
  • NOT NULL, PRIMARY KEY, and CHECK lists.
  • Foreign keys, so a child id comes from a parent row that was just generated.
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  city VARCHAR(80),
  created_at TIMESTAMP
);

Every table is generated, foreign keys are filled from the parent rows, and the row count goes up to 10,000.
