Reproducible SQL test data

A failing test is hard to share when the next run invents different customers. Type a seed before you generate. The same schema, the same row count, the same language, and the same seed produce the same rows. Leave Seed empty when you want a new set.

The number is shown under the preview after a run. Put that number back into Seed, or open a link that already includes it, and generate again. Nothing is stored on a server. The schema and the seed stay in this browser.

Foreign keys still come from the parent rows of that run, so the repeated file loads the same way. Chaos, if you turn it on, is part of the run: the same seed repeats the same messy cells.
