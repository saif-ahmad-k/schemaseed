Schema seed for a SQL database

A schema seed is a set of rows that match tables you already defined. SchemaSeed reads a CREATE TABLE statement, or a CSV header, and fills those columns with realistic test data. You download the seed as JSON, CSV, or SQL INSERT statements.

How to seed a schema

  1. Paste the tables. Include primary keys, NOT NULL, CHECK lists, and foreign keys.
  2. Check the generator next to each column. email becomes an email. created_at becomes a timestamp. A CHECK list is used as the only allowed values.
  3. Choose the database. PostgreSQL, MySQL, SQLite, and SQL Server are included. The SQL file inserts parent tables before child tables, so a foreign key points at a row that exists.
  4. Download the seed. Free covers the first table and 50 rows. Pro covers every table and up to 10,000 rows.
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  city VARCHAR(80)
);

That statement is enough to seed the schema. The rows stay in the browser until you download them. Close the tab and they are gone.

People also write this as “seed schema.” Both mean the same job here: start from the schema, produce rows that fit it, and load them with SQL or a CSV import.
